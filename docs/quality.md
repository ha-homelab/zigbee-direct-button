# Quality and OpenSSF assessment boundaries

This project contains shared C firmware, platform-specific HAL code, Python build/index/integration helpers, deployment examples and a published experimental firmware image. The application derives from a pinned upstream snapshot. Host simulation is useful evidence for shared behavior; it does not emulate the radio or validate every linked SDK function.

The inherited default host configuration assigns a cover to endpoint 10. An instrumented run on 2026-10-16 reproduced a global buffer overflow because a ten-element map was indexed by that one-based endpoint. The corrected maps reserve slot zero, enforce bounds on callback lookup and component allocation, and retain endpoint 10. The common cluster pool is sized for the worst allowed ten-endpoint configuration (38 entries, including battery and end-device poll control); a separate pre-setup budget guard checks each configuration. Stored and remotely written configuration lengths are validated before string access, and token parsing preserves the terminating NUL. Regression tests exercise the real shared C code, excessive component/endpoint inputs, malformed configuration strings and output-reader cleanup.

CI runs both ordinary and AddressSanitizer/UndefinedBehaviorSanitizer host variants, Python common-error diagnostics and CodeQL Python/Actions analysis. C CodeQL traces both host builds, covering shared application logic and the host HAL. It does not claim to analyze the Telink/Silabs target HAL or prebuilt SDK libraries. Sanitizer failures and real diagnostics must be fixed; do not disable checks to obtain a badge. Completed CI results apply only to their recorded revision. The final local Clang/ASan/UBSan run on 2026-10-16 passed 309 tests with Python warnings treated as errors; it did not compile the target radio firmware.

The [license assessment](license-assessment.md) preserves the nonstandard permissive upstream grant and separates the SDK's source inventory from linked prebuilt libraries. A complete firmware FLOSS claim and complete dependency-vulnerability assessment remain unestablished. The full commissioning, OTA authenticity, key-length and key-lifecycle profile is also unqualified. Do not substitute HTTPS source delivery or a source-only scanner result for those full-system requirements.

A public GitHub issue/private-report inventory and maintainer attestations are separate evidence. No physical acceptance, new stable release, full coverage percentage or backup maintainer is inferred from these changes.
